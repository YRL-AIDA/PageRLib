# Этап 2: Единая схема слова (Word schema uniform) — устранение KeyError 'font' в Rows2Regions

**Глобальный план:** [global.md](./global.md)  
**Дата создания:** 2026-10-16  
**Статус:** Выполнено (2026-10-16) — ADR-005 принят; кодовый фикс применён (вариант A) + дефект `Font({})` в `font.py`; регресс-тесты 13/13 и 7/7 прошли; спеки обновлены и согласованы documenter'ом  
**Связанный этап:** [00001-image-extractor.md](./00001-image-extractor.md) — именно он породил OCR-слова без `font`

---

## Цель

Устранить жёсткую зависимость конвейера `Rows2Regions` от поля `font` в слове, чтобы страница, полученная **любым** способом, обрабатывалась единообразно и без падения:

- **PDF-путь** → слова содержат реальные метаданные шрифта (`data["font"]`).
- **OCR/изображение-путь** → слова содержат только `data["text"]` и `data["confidence"]` (шрифта физически нет).

Ограничения (не нарушать):

1. **Не менять поведение модели/инференса.** Признаки строк строятся из геометрии, текста и пиксельного эмбеддинга шрифта (`FontEmbRowGLAMTokenizer.get_vec_font`, строки 303–308), а не из `word.data["font"]`.
2. **Сохранить реальные font-метаданные PDF** для `LogicalStructureExtractor` (определение заголовков по размеру/жирности/курсиву).
3. **Не «врать» в данные для OCR.** Для OCR шрифт не существует — не подставлять фейковый `font`. Отсутствие поля должно быть безопасным для всех потребителей; пустой `{}`/дефолт создаётся только там, где поле реально требуется для записи.
4. **Стиль безопасного доступа** уже принят в коде: `.get()` и проверки `"key" in dict`.

## Обзор

### Текущее состояние: дрейф схемы слова между продюсерами

| Путь | Продюсер слов | Файл, строки | Схема слова |
|------|---------------|--------------|-------------|
| PDF | `TextExtractor._create_word` | `src/pagerlib/file_input/pdf_as_json_model/miner_pdf_model/text_extractor.py:74-87` | `{"segment", "text", "font"}` (`font_info` из `LTChar`: `fontname`/`fontsize`/`is_normal`) |
| OCR | `Image2Words.extract_from_img` | `src/pagerlib/extractors/page_extractor/images2regions/image2words.py:71-87` | `{"text", "conf", "segment"}` — **без `font`** |

Каноническая нормализация в `Row._get_children_from_dict_list` (`src/pagerlib/dtypes/physical_elements/row.py:18-30`) уже **условная и безопасная**:

- `data = word_json["data"] if "data" in word_json else {"text": word_json["text"]}`
- `font` добавляется только `if "font" in word_json`
- `conf` → `data["confidence"]` только `if "conf" in word_json`

Итог: `Word.data` для OCR = `{"text", "confidence"}`, для PDF = `{"text", "font"}`.

### Проблема (корень)

`KeyError: 'font'` в `src/pagerlib/extractors/page_extractor/rows2regions/rows2regions.py:87`, функция `fix_row_this_image` (внутренний `get_rows`, строки 84–91):

```python
dict_row['words'] = [{"segment": w['segment'],
                     "text": w['data']['text'],
                     "font": w['data']['font']}   # ← падает здесь для OCR-слов
                    for w in dict_row['words']] if 'words' in dict_row else []
```

Это **единственный жёсткий доступ к `font` во всей кодовой базе** (проверено grep по `rows2regions/`). Ручная пересборка слова:

- вытаскивает `w['data']['text']` и `w['data']['font']` из вложенной схемы `{segment, data}`;
- строит «плоское» слово `{segment, text, font}`;
- далее `Row.from_dict(dict_row)` → `_get_children_from_dict_list` снова нормализует его обратно во вложенную схему `data = {"text", "font"}`.

Побочный эффект: для OCR-слов при пересборке **теряется `confidence`** (в плоское слово копируются только `segment`/`text`/`font`).

### Потребители `font` (все, кроме точки выше, безопасны)

| Потребитель | Файл, строки | Поведение при отсутствии `font` |
|-------------|--------------|----------------------------------|
| `_HeadingInfo._extract_font` | `src/pagerlib/extractors/document_extractor/logical_structure_extractor.py:30-46` | Читает `word.data["font"]` только `if "font" in word.data`, иначе `Font({})` с дефолтами (`size=-1 → 12.0`, `width=0.5`, `italic=0.0`). **Уже безопасен.** |
| dtype `Font` | `src/pagerlib/dtypes/physical_elements/font.py` | `Font({})` даёт дефолты; `set_width`/`set_italic` осторожны с отсутствием `fontname` (ветка `'bold' in dict_font['fontname']` не достигается, т.к. `name` пуст). |
| Токенизаторы | `src/pagerlib/extractors/page_extractor/rows2regions/rowsGLAM_tokenizer_20260826/rowsGLAM_tokenizer.py` | **Не читают** font-метаданные слова. Активный `FontEmbRowGLAMTokenizer` берёт шрифтовой вектор из пиксельного патча строки (`get_vec_font`, 303–308) и обёрнут в `_get_vec_font_safe` (275–280) с `try/except → нули`. Базовые признаки читают текст через `w.get('data').get('text', '')` (строка 128; также 195). |
| `Word.confidence` | `src/pagerlib/dtypes/physical_elements/word.py:19-21` | Производится OCR, хранится, но **нигде больше не потребляется**. |

### Вывод

Жёсткая зависимость локализована в одной функции. Потребители `font` уже написаны безопасно, а `Row._get_children_from_dict_list` — это точка канонической нормализации слова, которая поддерживает **обе** схемы.

## 2. Фикс Rows2Regions (устранение жёсткого доступа `font`)

**Исполнитель:** coder

### Предусловия

- [ ] Секция 2 может выполняться независимо от ADR (секция 1)
- [ ] Согласовано, что `Row._get_children_from_dict_list` — точка нормализации

### Вход

- `src/pagerlib/extractors/page_extractor/rows2regions/rows2regions.py` (функция `fix_row_this_image`, строки 83–142; внутренний `get_rows`, строки 84–91)
- `src/pagerlib/dtypes/physical_elements/row.py` (`_get_children_from_dict_list`, строки 18–30)
- `src/pagerlib/dtypes/physical_elements/base_physical_element.py` (`from_dict` 23–30, `to_dict` 41–48)

### Выход

- Исправленная `fix_row_this_image`, не требующая поля `font` в словах.
- Конвейер `Rows2Regions` работает и на PDF-словах (с `font`), и на OCR-словах (без `font`).

### Разбор: почему сейчас вообще пересобираются слова

`page_extract` (строки 25–28) строит строки как `{"text", "segment", "words": [word.to_dict() ...]}`. `word.to_dict()` (наследуется из `PhysicalElement.to_dict`) даёт **вложенную** схему `{"segment", "data"}`. Внутренний `get_rows` вручную «сплющивает» её в `{segment, text, font}` — но затем `Row.from_dict` → `_get_children_from_dict_list` всё равно нормализует обратно во вложенную схему. То есть ручная пересборка **избыточна** и именно она вносит жёсткий доступ к `font`.

Важно: `get_rows` применяется и к `image_rows` (строка 95), у которых **нет** ключа `"words"` (элементы списка `images` в `page_extract`, строки 29–31). Поэтому дефолт `words = []` сохранить обязательно.

### Задачи

#### Задача 2.1 (рекомендуемый вариант A): убрать ручную пересборку слов

**Файл:** `src/pagerlib/extractors/page_extractor/rows2regions/rows2regions.py`  
**Функция:** `fix_row_this_image`, внутренний `get_rows` (строки 84–91).

**Действия:**

1. Удалить пересборку `dict_row['words'] = [{"segment": w['segment'], "text": w['data']['text'], "font": w['data']['font']} ...]`.
2. Обеспечить наличие ключа `words` перед `row.from_dict(dict_row)` (эквивалент текущего `if 'words' in dict_row else []`), например через `setdefault('words', [])` — **не писать код здесь, реализует coder**.
3. Оставить `row = Row.get_none(); row.from_dict(dict_row); return row` как есть — нормализация полностью ложится на `Row._get_children_from_dict_list`, которая поддерживает:
   - вложенную схему `{"segment", "data"}` (это и есть вывод `word.to_dict()`);
   - отсутствие `font`/`conf` — безопасно;
   - наличие `font` (PDF) и `conf` (OCR) — переносятся в `Word.data`.
4. Проверить, что `fix_row_this_image` по-прежнему возвращает `[row.to_dict() for row in rows]` (строка 142) и что `get_region`/`regions_from_graph` продолжают получать строки с ключом `words`.

**Ожидаемый эффект:**

- Для PDF поведение **не меняется** (слова сохраняют `data = {"text", "font"}`).
- Для OCR падения нет; слова получают `data = {"text", "confidence"}` (поле `font` не выдумывается). `confidence` теперь не теряется — это соответствует опциональности `confidence` в модели данных и безопасно (потребителей нет).
- `font` не создаётся искусственно — выполнено требование «не врать в данные».

**Обоснование выбора A:** минимально по смыслу (удаление избыточного кода), устраняет корень дрейфа схемы, сохраняет `confidence`, не создаёт фейковый `font`.

#### Задача 2.2 (fallback вариант B): минимальный безопасный доступ

**Файл:** тот же.  
**Когда применять:** если вариант A выявит неожиданную регрессию в `regions_from_graph`/токенизаторе.

**Действия:**

1. Заменить жёсткий доступ на безопасный: `w['data'].get('font', {})` (и убедиться, что `w['data']['text']` присутствует у всех слов — у обоих продюсеров `text` обязателен).
2. Дополнительно заменить `w['data']['text']` на `w['data'].get('text', '')` для симметрии со стилем кода.

**Компромисс:** для OCR-слов создаётся пустой `font = {}` (запись в `data`), что допустимо пунктом 3 требований, но менее предпочтительно, чем A. `confidence` при этом по-прежнему теряется (как и сейчас).

> Решение A/B принимает coder по результатам задачи 3.1. При выборе B — отметить причину в комментарии и в финальном отчёте этапа.

## 3. Регрессионные тесты

**Исполнитель:** coder

### Предусловия

- [ ] Секция 2 выполнена

### Ключевое наблюдение для тестируемости

`Rows2Regions.fix_row_this_image(self, rows, image_rows)` **не использует `self`** (только `Row`, `ImageSegment`, `np`). Поэтому его можно тестировать без загрузки GNN-модели: через `Rows2Regions.fix_row_this_image(None, rows, image_rows)` или `object.__new__(Rows2Regions)`. Это делает юнит-тест лёгким и быстрым (без `get_load_model()`).

#### Задача 3.1: Юнит-тест `fix_row_this_image` на двух схемах слов

**Файл:** `tests/words_schema/test_word_schema_uniform.py` (создать)  
**Стиль:** pytest; запуск с `PYTHONPATH=src` (как в `tests/all_element/test_all_elements_extraction.py`, строки 11–35) или через `python -m pytest` из корня.

**Сценарии:**

1. **OCR-слова без `font` (регрессия на KeyError):**
   - Вход `rows`: строка с `words` в схеме `word.to_dict()` → `{"segment": {...}, "data": {"text": "hello", "confidence": 87.0}}`.
   - `image_rows`: список без ключа `words` (например `[{"text": "img", "segment": {...}}]`).
   - **Ожидание:** исключения нет; в возвращённых строках у слов сохранён `data["text"]`; `data` не содержит искусственного `font` (для варианта A); ключ `confidence` сохранён (вариант A).
2. **PDF-слова с `font` (регрессия на неизменность):**
   - Вход `rows`: слова в схеме `{"segment": {...}, "data": {"text": "Title", "font": {"fontname": "Times-Bold", "fontsize": 14, "is_normal": true}}}`.
   - **Ожидание:** исключения нет; `data["font"]` сохранён без изменений; результат по словам совпадает с текущим поведением.
3. **Смешанный случай:** в одном наборе строк есть и PDF-, и OCR-слова — оба обрабатываются без падения.
4. **`image_rows` без `words`:** обработка `image_rows` не падает (дефолт `[]`).

**Проверка отсутствия жёсткого доступа:** тест 1 должен падать на текущем коде (`KeyError: 'font'`) и проходить после фикса.

Если пакет установлен не как editable, правки в `src/` не попадут в место, откуда запускается пользовательский сценарий.
