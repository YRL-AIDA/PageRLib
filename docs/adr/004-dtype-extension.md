# ADR-004: Расширение типов данных — confidence и метаданные OCR

**Дата:** 2026-07-16
**Статус:** Принято
**План:** [00001-image-extractor.md](../plan/00001-image-extractor.md)

---

## Контекст

`Images2RegionsExtractor` применяет Tesseract OCR к изображениям и должен возвращать:
1. **Confidence scores** — на уровне отдельных слов (Tesseract выдаёт confidence 0..100 для каждого слова)
2. **Метаданные OCR** — статистика обработки (время, количество изображений, конфигурация)

Нужно решить, где и как хранить эти данные в пределах существующей модели `PageRDF`.

## Ключевые архитектурные принципы

1. **Минимальные изменения модели данных.** Существующая иерархия `PageRDF → Page → Region → Row → Word` уже покрывает все потребности. Новые классы — только при крайней необходимости.
2. **`Word.data` — расширяемый контейнер.** `Word.data` уже используется для хранения произвольных атрибутов (`text`, `font`). Добавление `confidence` в `data` не требует изменения схемы.
3. **Регион — естественный контейнер результата OCR.** `Image2Words.get_region()` уже возвращает `Region(Row(Word))`. Результат `Images2RegionsExtractor` должен следовать этому же контракту — `Region` из слов.
4. **Метаданные не должны загромождать модель.** PageRDF — это представление документа, а не лог обработки. Статистика OCR — артефакт процесса, а не свойство документа.

## Альтернативы

### 1. Хранение confidence

| Вариант | Описание | Плюсы | Минусы |
|---------|----------|-------|--------|
| **A. `Word.data["confidence"]`** | Добавить ключ `"confidence": float` в существующий `Word.data` | Минимальные изменения, `Word.data` уже гибкий контейнер, confidence — рядовая мета-информация как `font` | Неструктурированно: нет гарантии наличия ключа, нет типа |
| **B. `OCRWord(Word)`** | Новый подкласс `Word` с полем `confidence: float` | Типобезопасность, явное отделение OCR-слов от обычных | Раздувание иерархии: ради одного поля — новый класс, ломает `isinstance`-проверки, усложняет сериализацию |

### 2. Хранение метаданных OCR

| Вариант | Описание | Плюсы | Минусы |
|---------|----------|-------|--------|
| **A. Не хранить** | Метаданные не сохраняются в `PageRDF`. Пользователь может измерить время сам, если нужно | Простота, `PageRDF` остаётся чистым представлением документа, никакого замусоривания `metadata` | Пользователь не может получить статистику из `prdf` после обработки |
| **B. `PageRDF.metadata["ocr_info"]`** | Словарь `{"extraction_time": float, "total_images": int, ...}` в `prdf.metadata` | Вся статистика под рукой, один источник правды | `metadata` замусоривается служебной информацией. Разные экстракторы будут писать в `metadata` разное — конфликты ключей. |
| **C. `OCRResult` — отдельный контейнер** | Новый объект `OCRResult` со статистикой, не связанный с `PageRDF` | Чистое разделение: документ отдельно, метаданные обработки отдельно. Не засоряет модель. | Избыточно для v1: ради трёх полей создавать новый тип и новый контракт. |

## Решение

**Приняты вариант A для confidence и вариант A для метаданных.**

### Confidence: `Word.data["confidence"]`

```python
class Word(PhysicalElement):
    @property
    def confidence(self) -> float | None:
        """Confidence OCR (0..100) или None, если слово не из OCR."""
        return self.data.get("confidence", None) if self.data else None
```

- `confidence` добавляется как ключ в существующий `Word.data` dict
- Свойство `Word.confidence` — синтаксический сахар для удобства доступа
- `Image2Words.extract_from_img()` добавляет `"conf": float` в словари слов при парсинге вывода Tesseract
- `Region` собирается через `Row._get_children_from_dict_list()` — никаких изменений в `Row` и `Region`

### Метаданные: не храним

Статистика OCR (время обработки, количество изображений, конфигурация Tesseract) **не сохраняется** в `PageRDF`:

- `prdf.metadata` не модифицируется — `PageRDF` остаётся чистым представлением документа
- Пользователь, которому нужна статистика, делает замеры самостоятельно на вызывающей стороне
- В будущем, если потребуется, метаданные могут быть добавлены отдельным контейнером (вариант C) без изменения модели `PageRDF`

### Регион собираем из слов

Результат OCR одного изображения — это **один `Region`**, собранный из слов:

```
Image (data["array"]: np.ndarray)
  │
  ▼ Image2Words.get_region(image)
Region
  └── children: list[Row]
      └── Row.children: list[Word]
          └── Word.data: {"text": str, "confidence": float}
```

- `Image2Words.get_region()` строит `Region(Row(Word))` — это существующий контракт, ничего не меняется
- `Images2RegionsExtractor.page_extract()` добавляет полученный `Region` в `page.children` рядом с исходным `Image`
- Сортировка `page.children` выполняется базовым классом `BasePageExtractor`

## Последствия

### Положительные

- **Ноль новых классов.** Ни `OCRWord`, ни `OCRResult`, ни других типов. Только одно свойство в `Word`.
- **Совместимость.** `Word.to_dict()` и `Word.from_dict()` продолжают работать без изменений — `data` сериализуется как dict, `confidence` внутри него.
- **Чистая модель.** `PageRDF` остаётся представлением документа, не замусоривается логами обработки.
- **Существующий контракт.** `Image2Words.get_region()` уже возвращает `Region(Row(Word))` — никаких изменений в сигнатурах.

### Отрицательные

- Нет встроенной статистики — пользователь не может после вызова `extract()` узнать, сколько изображений обработано и сколько времени это заняло. При необходимости — делает замеры сам.
- `Word.data["confidence"]` не имеет гарантии типа на уровне Python (это компромисс гибкости `data`-контейнера).

### Требующиеся изменения

1. `Word` — добавить property `confidence` (синтаксический сахар над `data.get("confidence")`)
2. `Image2Words.extract_from_img()` — добавить `"conf": float` в словари слов
3. `Images2RegionsExtractor` — **не** писать в `prdf.metadata`
4. Спецификация `docs/project/specs/image_extractor_spec.md` — убрать `ocr_info` из `PageRDF.metadata`, заменить `BaseDocumentExtractor` на `BasePageExtractor`
